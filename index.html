EventShield Replay yesterday's Kafka traffic through tomorrow's build, and diff what it did.

GoKafka / MSKKubernetes / EKSClickHouseTerraform

A Kafka consumer can pass every unit test and still behave differently in production, because the inputs that break it only exist in production. EventShield takes a sample of real events, runs them through the current build and the candidate build at the same time in an isolated sandbox, records every side effect each one produced, and compares them event by event. If the candidate does something the current build didn't, the deploy gate says no.

how it works

Same input, two builds, one comparison per event

A run is a pipeline with a fork in the middle. Everything before the fork happens once. Everything after it happens twice, once per side, and the two halves never see each other until the diff.

Sample
Take N events off the production topic. Each one keeps its (topic, partition, offset) as its identity.
Replay
Republish the sample onto two per-run replay topics, one per side, with the event id in a header.
Execute
Both builds consume their own replay topic.
baseline · today's imagecandidate · the new image
Capture
Kafka outputs and HTTP calls are recorded, tagged with the event that caused them.
baseline effectscandidate effects
Diff
Effects are re-keyed by event id onto one topic, so a pool of workers can compare in parallel.
Verdict
A policy turns diff rate, error rate and p95 latency into PASS or FAIL, and a CI exit code.

The comparison is only meaningful if a few things hold:

  • correlationEvery side effect carries the id of the event that caused it. The SDK puts it there, so a service can't forget. Without this there is nothing to compare.
  • determinismThe shadow consumers read only their per-run replay topics, never production, so a run is reproducible from its archived sample.
  • isolationThe candidate is untrusted code. It runs in its own namespace with no way out except to the shadow broker. Proven below.
  • idempotencyDiffs are keyed so that re-processing an event after a crash writes the same row, not a second one. Retries are safe by construction.
  • behavior, not implementationOnly what a service does to the outside world is compared. Internal state and logs are its own business.
  • completionA run is done when every consumer group's lag is zero, not when a timer runs out.
isolation

The candidate can't reach anything it shouldn't

The build under test might be broken, or might be malicious, and EventShield has to be safe to run either way. Each run gets a fresh Kubernetes namespace with a default-deny egress policy, a service account with no API token, and an allowlist with exactly one entry: the shadow broker, on its port.

I wanted a test that would fail if it weren't true, so a probe pod runs inside the sandbox and tries to get out. It has to be blocked from the internet by raw IP as well as by hostname, because a hostname-only test can't tell "egress blocked" from "DNS blocked". And it has to succeed at reaching the shadow broker, because a pod with no network at all would pass every other check for the wrong reason.

what I built

One Go module, from SDK to Terraform

sdk/goThe library a service embeds. Pulls the event id out of each record into the handler's context and stamps it onto every Kafka record and HTTP call the handler makes.
pipeline · comparatorSample, replay, capture, and a per-event diff engine with rules: ignore a field, allow numeric tolerance, treat an array as a set.
storage · state · metaClickHouse for diffs (ReplacingMergeTree, so retries are idempotent), Redis for counters and leases, Postgres for the run registry.
kubernetesThe sandbox controller: namespace per run, Calico default-deny, token-less service account, and the probe that proves it.
api · orchestrator · gateREST API, a poller that leases queued runs and executes them, and the policy that turns metrics into an exit code CI can act on.
capture-proxyAn egress proxy the sandbox routes HTTP through, so outbound calls get recorded and correlated instead of leaving.
deploy/terraform · helmVPC, EKS, MSK with IAM auth, RDS, ElastiCache, S3, ECR, least-privilege IRSA roles. One command up, one command down, a budget alarm in between.
dashboardA Next.js console over the API: latency, error rate, and the diffs, per run.
